# Reachability reflection after P2-004

## Audit outcome

The rapid sequence changed the research decision twice without building more
infrastructure:

1. P2-002b showed that outcome mixing was not the missing ingredient in the
   capability predictor.
2. P2-002c showed that a compact relational repair still did not beat the
   intervention null by the frozen margin.
3. P2-003 converted a post-hoc immovable-cell clue into a frozen exhaustive
   mechanism test and passed 7,440 of 7,440 cases.
4. P2-004 tested the complementary moveable-cell mechanism on a new exhaustive
   size and passed 90,720 of 90,720 cases.

The valuable move was not writing more predictor code. It was changing the
question from "which features correlate with recovery?" to "was recovery
possible under the available actions?"

## Contribution to the long-term agenda

The programme now has an operational distinction it previously lacked:

```text
target unreachable  !=  reachable target not realized  !=  robust recovery
```

This matters for goal discovery. A system cannot be judged incompetent for not
reaching a state excluded by its post-intervention action graph. Conversely,
reachability alone is not goal-directedness; it only defines the opportunity
set against which regulation, compensation, and adaptation can be evaluated.

## Time-allocation decision

- Stop representation fitting on the existing P2-002 labels.
- Stop exhaustive size scaling after the independent size-6 pass; it would add
  confidence without changing the current decision.
- Keep the existing NetLogo and linked workbench as inspection tools, but add no
  visualization machinery until a new scientific comparison needs it.
- Spend the next bounded sprint on an off-the-shelf state-graph reachability
  baseline for multiple local rules. The first artifact is a table separating
  reachable, realized, and robust outcomes—not a dashboard.

## Next gate

Advance only if opportunity-adjusted realization differs across algotypes or
schedules in held-out cases. If exact reachability already explains every
outcome, record the system as mechanically complete and move to a richer
generator rather than adding complexity here.
